# Conventions

## Python

- Stdlib only. No external dependencies are added.
- Scripts use `argparse` subcommands and a dispatch dict in `main()`.
- `sqlite3` is used directly with `row_factory = sqlite3.Row` for dict-like access.
- All SQL uses parameterized queries (`?` placeholders). Never f-string or
  string-format SQL with user input.
- WAL journal mode is set on every connection.
- `SKILL_DIR`, `DB_PATH`, and `REF_DIR` are resolved from `__file__` so the
  database location is stable regardless of cwd.

## SQLite schema

- `rules`: primary table. `rule_id` is TEXT PRIMARY KEY (e.g. `SR-101`).
- `rule_versions`: auto-versioning archive. `cmd_update` copies the old row
  here before overwriting.
- `facts`: autoincrement `fact_id`. Facts have no stable ID (unlike rules).
  Identity is the `(domain, text)` pair.
- `usage_log`: audit entries for rule consultations.
- `init_db` uses `CREATE TABLE IF NOT EXISTS` — idempotent, but no migration
  support for schema changes.

## Design principles (from README/SKILL.md)

- Tier (1 vs 2) decides WHETHER a rule loads. Priority (HIGH/MED/LOW) decides
  which rule WINS when two loaded rules conflict. Equal priority + real
  conflict means ask the user, never guess.
- Rules are never deleted — mark disabled or deprecated in place with date
  and reason.
- Facts are never phrased as rules; rules never store data.
- Mandatory rules must never be silently dropped for token budget: if tier-1
  + matched rules don't fit, report the constraint and stage the work.
- Markdown views under `references/` are generated by `export-md`, never
  hand-edited.

## Testing

- Test framework: `unittest` (stdlib, no dependencies).
- Tests live in `tests/` and import `rules_db` from `scripts/` via `sys.path`.
- Each test uses a temp directory and monkeypatches `rules_db.DB_PATH` and
  `rules_db.REF_DIR` to avoid touching the real database.
- Run all tests:
  ```bash
  python -m unittest discover -s tests -p "test_*.py" -v
  ```
- Run a single test module:
  ```bash
  python -m unittest tests.test_seed_facts -v
  ```

## Git

- Commit messages are concise, no trailing period. Case varies (recent commits
  use sentence-case; earlier ones use lowercase).
  Examples: "Fix fact duplication on re-seed: skip existing facts by domain+text",
  "Add measured performance section".
- Development is on `main` directly.
- Git identity is passed inline via `git -c user.name=... -c user.email=...`
  when no local or global config is set, to avoid modifying config files.

## Write gate (before adding any rule to the DB)

1. Classify: standing constraint to rule; numbered procedure to task skill;
   time-bound one-off to nothing.
2. Duplicate check: `query --match` the topic first; same topic to update, not add.
3. Contradiction check: conflicts with existing rule to surface both, ask which wins.
4. User approval: corrections/suggestions are not auto-promoted.
5. Assign ID + priority + domain + tags, then `add` and `export-md`.
